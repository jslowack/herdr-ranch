# Stacked PRs in the PRs List Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show a stack of dependent PRs as one tree row in the PRs list, and let one agent review the stack or make it merge-ready.

**Architecture:** Stacks are worked out once per load, in a new pure module `stacks.js`, from the PR list the mod already fetches (plus `baseRefName`). `main.js` turns them into list items (a stack row, then its layers indented). Two new agent modes of a new kind `stack` live in `shared/prompts.js`, and the shared Start agent dialog runs them like the existing modes.

**Tech Stack:** Herdr mod JavaScript (`gpui-kit`, `gpui-base`, `herdr`), `gh` CLI, `gh stack` extension (fix mode only), tests under `node --test` with the stubs in `tests/stubs/`.

**Spec:** [#9](https://github.com/jslowack/herdr-ranch/issues/9), plus two answers given after filing: a stack is named after its bottom PR's title; under a search or filter, a stack shows whole with its non-matching layers dimmed. Mockup: `herdr-ranch-prs/prototype-stacks.html`, variant A.

## Global Constraints

- A stack: a chain of **open, non-fork** PRs where a PR's `baseRefName` is another such PR's `headRefName`. At least 2 layers. No `gh stack` needed to see stacks.
- The stack row: a `stack` pill, the bottom PR's title, `N PRs into <trunk>`, and the blocker line.
- **Fix stack to merge** needs `gh stack`; without it the action shows "Needs gh stack" and the hint `gh extension install github/gh-stack`. Stack rows and **Review stack** work without it.
- The agent never merges. The mod itself writes nothing to GitHub.
- Edit `shared/` first, then copy each changed file over its copy in `herdr-ranch-issues`, `herdr-ranch-prs` and `herdr-ranch-reviews` (`install.sh` and CI fail on a stale copy).
- No em dashes or en dashes in prose, comments or strings.
- Renders stay cheap (Herdr interrupts a render after about 50 to 100 ms): stacks are computed at load, never in `render`.

## Review Focus

1. **A lower layer already merged** (its PR closed, branch kept): only open PRs form stacks, so the rest is a shorter stack or a loose PR, never a layer pointing at nothing. Test in Task 1.
2. **A base cycle** (A's base is B's head and B's base is A's head): detection must end and show both as loose PRs. Test in Task 1.
3. **A fork PR with the same branch name as a layer** (`main`, `fix`): forks never join a stack. Test in Task 1.
4. **A branching stack** (two PRs on the same layer): one stack, depth-first, children by number, level = depth. Test in Task 1.
5. **A search that matches only a middle layer:** the whole stack shows, the other layers dimmed, and the "This branch" pin still works for a layer. Manual check in Task 4.

The two defaults, as exact copy:

```text
stack-review:
Review the stack of {count} pull requests "{title}" into {trunk} ({repo}). Layers, bottom first:
{layers}

This is a read-only review: do not push, comment, approve, request changes, or write to GitHub in any other way.

1. Check out the top layer in this worktree: `gh pr checkout {top} --detach`.
2. Review each layer on its own diff, bottom first: `gh pr diff <number>` and `gh pr view <number> --comments`.
3. Check that each layer builds only on the layers below it, and that together they tell one story.
4. Build the top layer and run the tests that cover the change.
5. Report findings per layer, ranked by severity, each with a file:line reference and a concrete failure scenario.

stack-fix:
Get the stack of {count} pull requests "{title}" into {trunk} ({repo}) ready to merge. Layers, bottom first:
{layers}

What blocks the merge:
{blockers}

Use the gh stack extension, always non-interactively (`gh stack view --json`, never the plain TUI).

1. Check out the stack: `gh stack checkout {top}`. If another local stack claims these branches, run `gh stack unstack --local` first. If this isn't a gh stack yet, adopt its branches: `git fetch origin`, then `gh stack init --base {trunk} <the branches, bottom first>`.
2. Fix the blockers from the bottom layer up: failing checks (`gh pr checks <number>`, then `gh run view <run> --log-failed`) and review comments (`gh api repos/{repo}/pulls/<number>/comments`), each with a focused commit on that layer's branch.
3. After changing a layer, run `gh stack rebase --upstack`, then the tests of the layers above.
4. Push with `gh stack push`.

Never merge, and do not comment, reply or resolve threads on GitHub. When done, list each blocker with what you changed, or why you didn't.
```

### Task 4: Stack rows in the list

**Files:**
- Modify: `herdr-ranch-prs/mods/herdr-ranch-prs/main.js` (load at `main.js:239-240`, `items()`, `row()`, `render`; add `"stacks"` to `KEPT`)

**Interfaces:**
- Consumes: `stacks`, `stackOf` (Task 1).
- Produces: list items `{ key, stack: Stack }` for a stack row and `{ key: "pr-<n>", data, level, dim }` for a layer; `this.collapsed: Set<string>` of stack keys.

Decisions for this task:
- `this.stacks = stacks(prs)` and `this.inStack = stackOf(this.stacks)` next to `this.data` and `this.hay` in the load, never in `render`.
- In `items()`, a group holds its loose PRs plus the stacks whose `group` is that group, stacks first. A layer never shows as a loose row. The group count counts a stack as one.
- A stack shows when any layer passes the search and filter. A layer that doesn't pass is `dim: true` (title and number in `muted`). The cache key also covers `this.collapsed`.
- The stack row: a chevron (click toggles `this.collapsed`, expanded by default), a `stack` pill in `ansi4`, the name (semibold, truncated), `N PRs into <trunk>` in `dim`, the blocker (`ansi1` unless it is `ready to merge`, then `ansi2`), then **Review stack** and **Fix stack to merge**. The buttons always show: Herdr runs no script on hover, so a hover-only reveal is out. Below 520px the buttons go on a second line.
- Layer rows are the normal row with a left indent of `12 * level` px and the level number in `muted`, `fs.tiny`, before the state icon.
- Up/Down move over the layers of expanded stacks and the loose PRs (`flat`); stack rows aren't a stop. Enter opens a layer's page as today.
- "This branch" pins a layer like any PR.
